# Context Panel → Editor Agent Routing & Insertion

**Date:** 2026-02-27
**Status:** Approved

---

## Overview

When the user is on a content editor page, the context panel chat should automatically route to the content-agent, and agent tool results (insertText, insertHeading, etc.) should stream directly into the PlateJS editor in real-time. Content is saved to the database after each insertion. Additionally, a passive writer prompt is shown in the info panel when the content has no writer linked.

---

## Goals

1. **Auto-routing** — No manual mode selection when on an editor route. The URL determines the agent and context.
2. **Tool-to-editor bridge** — Writer-agent tool results (insert/replace/format) are intercepted from the SSE stream and applied directly to the Plate editor.
3. **Auto-save** — Each tool insertion triggers a DB save.
4. **Writer prompt** — Passive banner in the info tab when content has no `writerId`.

---

## Architecture

### Agent Hierarchy (unchanged)

```
platformRouterAgent
└── contentAgent (pure orchestrator — no tools)
    ├── writerAgent         ← executes editor tools
    ├── researchAgent
    ├── seoAuditorAgent
    └── reviewerAgent
```

Content-agent remains a pure router with `tools: {}`. Sub-agents, primarily writer-agent, call editor tools. Tool-result events bubble up through the full stream from `platformRouterAgent.stream()`.

## Piece 1 — chatContextStore (URL-Reading Store)

**File:** `apps/web/src/features/teco-chat/stores/chat-context-store.ts`

A TanStack Store that derives agent routing and content context from the current URL. Updated reactively as the user navigates.

```typescript
interface ChatContextState {
  mode: "auto" | "content";
  contentId: string | null;
}
```

**Sync hook:** `useSyncChatContext()` — runs inside the dashboard layout. Reads `useRouterState()` or `useParams()` from TanStack Router. When the URL contains a `$contentId` param, sets `mode: "content"` and `contentId`. On any other route, resets to `mode: "auto"`, `contentId: null`.

**Changes to `useTecoRuntime`:**
- Drops the `mode` prop
- Reads `mode` and `contentId` from `chatContextStore` via a ref (same `useEffect` → ref pattern as current `modeRef`)
- Sends both in the request body to `/api/chat`

**Changes to `TecoChatTab`:**
- Removes the `mode` useState + `onModeChange` prop
- Calls `useTecoRuntime({ teamId })` — no mode passed

**Changes to `Thread` composer:**
- Mode selector (`<Select>`) hidden when `chatContextStore.mode === "content"` (URL controls it)
- Shown with an indicator "Contexto: [content title]" when in content mode (optional enhancement)

## Piece 2 — EditorAwareChatTransport (SSE Interception)

**File:** `apps/web/src/features/teco-chat/transports/editor-aware-chat-transport.ts`

Replaces `AssistantChatTransport` in `useTecoRuntime`. Wraps the `/api/chat` fetch, reads `chatContextStore`, and intercepts tool-result SSE events for editor operations.

### Request changes

Adds `contentId` to the request body when in content mode:

```typescript
body: async () => {
  const threadId = await ensureThread();
  const { mode, contentId } = chatContextStore.state;
  return { teamId, threadId, mode, contentId };
}
```

### SSE stream interception

Uses a `TransformStream` to parse each SSE chunk. When a `tool-result` event is detected with an editor tool ID, it calls the editor bridge:

**Editor tool IDs to intercept:**
- `insert-text` → `editorBridge.insertMarkdown(result.markdown, result.position)`
- `insert-heading` → `editorBridge.insertHeading(result.text, result.level)`
- `insert-list` → `editorBridge.insertList(result.items, result.listType)`
- `insert-code-block` → `editorBridge.insertCodeBlock(result.code, result.language)`
- `insert-table` → `editorBridge.insertTable(result.markdown)`
- `replace-text` → `editorBridge.replaceText(result.oldText, result.newText)`
- `format-text` → `editorBridge.formatText(result.format, result.target)`
- `propose-suggestion` → `editorBridge.proposeSuggestion(result.suggestion)`

All events (including intercepted ones) pass through to the thread runtime so the assistant-ui Thread still shows status/summary.

### Thread display during insertion

- While streaming: thread shows standard assistant-ui thinking/streaming indicator
- On tool-result for editor tools: thread does NOT render the raw tool result content
- On stream finish: thread renders a summary message (generated by the agent as its final text response, e.g. "Inseri 3 parágrafos sobre X no editor.")
- The actual content is visible in the editor, not in the thread

### Editor bridge interface

A thin object registered by `PlateEditor` on mount:

```typescript
interface EditorBridge {
  contentId: string;
  insertMarkdown: (markdown: string, position: string) => void;
  insertHeading: (text: string, level: number) => void;
  insertList: (items: string[], type: "ul" | "ol") => void;
  insertCodeBlock: (code: string, language: string) => void;
  insertTable: (markdown: string) => void;
  replaceText: (oldText: string, newText: string) => void;
  formatText: (format: string, target: string) => void;
  proposeSuggestion: (suggestion: string) => void;
  triggerSave: () => void;
}
```

**Store:** `editorBridgeStore` (TanStack Store) at `apps/web/src/features/editor/stores/editor-bridge-store.ts`

```typescript
interface EditorBridgeState {
  bridge: EditorBridge | null;
}
```

- `PlateEditor` calls `registerEditorBridge(bridge)` on mount, `unregisterEditorBridge()` on unmount
- `EditorAwareChatTransport` reads `editorBridgeStore.state.bridge` — if null, skips editor interception

### Auto-save

After each tool-result is applied to the editor, `bridge.triggerSave()` is called. `EditorPage` exposes `triggerSave` which calls the existing `updateContent` mutation (same as the auto-save onChange path).

## Piece 3 — Writer Prompt in Info Panel

**Component:** `WriterPromptBanner`
**Location:** Rendered above `EditorMetaPanel` in the info tab, when `content.writerId` is null and the user has not dismissed it for this content.

### Dismiss behavior

Stored in `localStorage` under the key `writer-prompt-dismissed-${contentId}`. No DB write. Stays dismissed per content across sessions.

### Layout

Inside the existing `ContextPanel` pattern — a distinct section with:

- Icon: `UserRound`
- Heading: "Personalize o escritor"
- Body: "Com um escritor configurado, o Teco aprende seu tom, estilo e objetivos para gerar conteúdo mais alinhado com a sua voz."
- Actions (two buttons, small):
  - **"Selecionar escritor"** — opens the writer selector via `useCredenza()`. If writer selector credenza doesn't exist yet, links to `/settings/writers`.
  - **"Pular"** — sets localStorage flag, hides the banner

### Integration

`EditorPage` passes `writerId` to the info tab content. The info tab renders:

```
<WriterPromptBanner contentId={contentId} writerId={writerId} />
<EditorMetaPanel meta={meta} onSave={handleMetaSave} />
```

## API Changes

### `/api/chat` route

Reads `contentId` from body. When present:
- Adds `contentId` to `requestContext` passed to `platformRouterAgent`
- Auto-adds `"[Usar content-agent]:"` prefix to the last user message (same as current `content` mode behavior)

```typescript
const { messages, threadId, mode = "auto", contentId } = body;
```

`requestContext` already supports `contentId` — no agent changes needed.

## Out of Scope

- Writer selector credenza UI (if it doesn't exist, the button links to `/settings/writers`)
- Changing content-agent tools (stays as pure orchestrator)
- Changing writer-agent tools (all existing tools remain unchanged)
- Character-level streaming from tool results (insertion is block-by-block per tool call)
